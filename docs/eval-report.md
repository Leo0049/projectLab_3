### What the completeness audit added, and why

The suite was 82 cases before an explicit audit of "claims made vs claims
tested". The gap analysis found three defects that no existing test could have
caught, because each one failed silently:

1. **`RedisRateLimiter` was never constructed, in any environment.** Backend
   selection used `@ConditionalOnMissingBean` in user configuration, which is
   evaluated before auto-configuration registers Redis, so the in-memory
   limiter always won. A multi-instance deployment would have allowed N times
   the configured rate while every quota test still passed. Now selected
   explicitly, and startup fails rather than degrading.
2. **`MaskingEngine` threw on any record whose declaring class was not
   public** — it called `setAccessible` on the canonical constructor but not on
   the component accessors. Production DTOs happen to be public, so it never
   surfaced.
3. **Two of the three sales templates had never executed.** The tool fixtures
   only ever passed `groupBy=STORE`, leaving `sales.summary_by_day` and
   `sales.summary_by_product` as unrun SQL.

Two smaller items were fixed alongside: `inventory.single` and
`BusinessQueryService.singleProduct` were dead code, and the test seed's line
items did not sum to their order totals, so revenue by store and revenue by
product disagreed for the same period.
